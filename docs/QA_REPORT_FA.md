# گزارش کنترل کیفیت پروژه

## کنترل‌های انجام‌شده در محیط ساخت

- بازبینی ساختار ۱۰ صفحه و ۶۱۲۰ خط فایل متنی فرانت اولیه
- بررسی نحوی تمام فایل‌های Python با `compileall`
- بررسی نحوی تمام فایل‌های JavaScript با `node --check`
- کنترل تمام نام‌های `{% url %}` استفاده‌شده در Templateها
- کنترل وجود تمام فایل‌های ارجاع‌شده با `{% static %}`
- کنترل وجود Migration اولیه برای `accounts`, `catalog`, `core`, `orders`
- کنترل نبود مسیر Static یا Route نام‌گذاری‌شدهٔ مفقود
- کنترل اسکریپت‌های Shell با `bash -n`
- نگهداری کامل نسخهٔ اولیه در `legacy_frontend/`

برای تکرار کنترل‌های مستقل از Django:

```bash
python scripts/preflight.py
```

پس از نصب وابستگی‌ها، کنترل‌های Runtime را اجرا کنید:

```bash
python manage.py check
python manage.py makemigrations --check --dry-run
python manage.py migrate
python manage.py test
```

## سناریوهای تست خودکار نوشته‌شده

- ثبت‌نام و اجبار نقش `STUDENT`
- جلوگیری از ایمیل تکراری
- Redirect کاربر ناشناس و پاسخ واقعی 403 برای نقش نامعتبر
- جلوگیری از افزودن دوره تکراری به سبد
- محاسبه قیمت و Snapshot در سرور
- پرداخت آزمایشی، ساخت Payment و صدور Enrollment
- جلوگیری از خرید دوباره یک دوره
- ممنوعیت نظر برای غیرخریدار و ثبت نظر خریدار با وضعیت Pending

## محدودیت محیط ساخت

محیط ساخت به اینترنت و بسته‌های Django دسترسی اجرایی نداشت؛ بنابراین `manage.py check`، اجرای Migration روی SQLite و تست‌های Runtime در همین محیط اجرا نشدند. فایل‌های Migration، تست‌ها، دادهٔ Seed و اسکریپت راه‌اندازی آماده‌اند و چهار فرمان بالا باید پس از نصب `requirements.txt` اجرا شوند. این محدودیت به‌جای ادعای اجرای نادرست، صریح ثبت شده است.
